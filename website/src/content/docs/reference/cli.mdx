## Usage

```bash
blackhole-threats [-conf PATH] [-feed SOURCE]... [-check-config | -once] [flags]
blackhole-threats -version
```

Flags take one dash, as in the man page, though Go also accepts two (`--conf`). A value can follow
the flag after a space or an equals sign: `-refresh-rate 30m` or `-refresh-rate=30m`. A boolean
flag is on when it's given; `-once=false` turns it off again. Without `-conf` the daemon reads
`blackhole-threats.yaml` from the working directory.

## Running

<FlagTable flags={running} />

With neither `-check-config` nor `-once` the daemon runs until it's stopped, refreshing on the
timer and on `SIGUSR1` or `SIGHUP`. `-check-config` wins if you give both.

## Logging

<FlagTable flags={logging} />

`-log-level warn` writes warnings as `level=warning`. Both flags are checked before the config is
loaded, so a bad value stops the daemon before anything else.

## Information

<FlagTable flags={info} />

`-version` prints three lines: `blackhole-threats` and the version, then `commit:` and `built:`
with the commit and the build date. A release build shows its tag, such as `v1.2.3`; a source
build shows `git describe` output for the checkout. The Debian package's binary shows the
package's upstream version without the `v`, such as `1.2.3`, and `commit: debian`.

`-h` or `-help` prints the flags and their defaults to standard error and exits with code 0. An
unknown flag or a value that won't parse, such as `-refresh-rate soon`, prints the same list after
the error and exits with code 2. [Signals and exit codes](/blackhole-threats/reference/signals-and-exit-codes/)
has the rest.
