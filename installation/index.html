Getting started/Installation

Installation

The signed APT repository, a single Debian package, the container image, release archives and source builds.

Every stable release publishes:

  • archives for Linux amd64, arm64 and arm, each holding one statically linked binary
  • Debian packages for amd64, arm64 and armhf, the Debian source package, and a signed APT repository with binary and source indexes
  • a container image on GHCR for linux/amd64 and linux/arm64
  • a sha256sums.txt covering the archives and packages

Release candidates use tags like v1.2.3-rc.1. They get archives, packages and an image tag of their own on GitHub, but the APT repository and the image’s latest tag only ever carry stable releases.

Signed APT repository

Section titled “Signed APT repository”

On Debian and Ubuntu hosts this is the recommended way to run it. Add the archive key and the source, then install:

The repository is signed with C578 26C0 5CD8 943F 7E33 46A8 9DEB A2D2 B18C 8A1D. Check that the published fingerprint the second command prints matches it before you go on.

The repository lives at the root of this site, beside the docs. It has a deb-src index too, so apt source blackhole-threats fetches the Debian source package.

The package puts the binary in /usr/sbin, the example config in /etc/blackhole-threats.yaml and a systemd unit in place, and starts the service. Debian package covers what to do next, and Files and paths lists everything it installs.

A single Debian package

Section titled “A single Debian package”

To install one package without adding the repository, download it from the release and let apt install it:

Swap amd64 for arm64 or armhf as needed. A package installed this way doesn’t update with apt upgrade.

Container

Section titled “Container”

The image is on GHCR. Mount a directory at /config and publish the BGP port:

On first start it writes a placeholder config to config/blackhole-threats.yaml and runs with it, so edit that file and restart the container. Container has the details.

A stable release is tagged with its version both with and without the v (v1.2.3 and 1.2.3), its minor line (1.2) and latest. A release candidate is tagged with its own version (v1.2.3-rc.1) and rc.

Release archives

Section titled “Release archives”

Each archive holds a single binary named for its platform, such as blackhole-threats-linux-amd64. Check it against sha256sums.txt, then install it wherever you keep system binaries:

The archive has no config, unit file or man page. Start from the example config and run the binary under whatever supervises your services.

From source

Section titled “From source”

Source builds use your Go toolchain and the Makefile, which stamps the version, commit and build date from git into the binary:

The binary is dist/blackhole-threats. make build-cross GOOS=linux GOARCH=arm64 OUTPUT=dist/blackhole-threats-linux-arm64 cross-compiles, and make package builds the Debian package on a Debian host.

Upgrading

Section titled “Upgrading”

With the APT repository, sudo apt update && sudo apt upgrade picks up new stable releases, and your edits to /etc/blackhole-threats.yaml are kept. With the container, pull the new tag and recreate the container. Either way the daemon restarts, which drops its BGP sessions until it’s back and has refreshed.

Check which version you’re running with blackhole-threats -version.

Overview

blackhole-threats

Turns threat feeds into BGP blackhole routes: it reads text and JSON feeds, summarises the prefixes and announces them to your routers with a community they can drop on.
