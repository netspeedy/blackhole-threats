Reference/Config keys

Config keys

Every key in the blackhole-threats YAML file, the GoBGP settings it passes through, and what makes the file fail to load.

The config is one YAML document with three top-level keys: gobgp, feeds and the optional limits. It’s decoded strictly: a key blackhole-threats or GoBGP doesn’t know stops the daemon rather than being ignored. The configuration guide walks through writing one.

Required keys

Section titled “Required keys”
KeyTypeWhat it is
gobgp.global.config.asintegerThe local ASN. Can’t be 0.
gobgp.global.config.routeridstringThe BGP router ID, which must be an IPv4 address. It’s also the next hop on announced routes.

Everything else is optional, though without gobgp.neighbors nobody receives the routes and without feeds there are none to send.

gobgp.global.config

Section titled “gobgp.global.config”
KeyTypeDefaultWhat it is
asintegernoneThe local ASN
routeridstringnoneThe router ID, IPv4
portinteger179The port GoBGP listens on. -1 turns listening off, so GoBGP only dials out.
localaddresslistlist of strings["0.0.0.0", "::"]The addresses GoBGP listens on

gobgp.neighbors

Section titled “gobgp.neighbors”

A list, one entry per peer.

KeyTypeDefaultWhat it is
config.neighboraddressstringnoneThe peer’s address, IPv4 or IPv6
config.peerasintegernoneThe peer’s ASN. The same as as makes it iBGP.
config.portinteger179The port to dial on the peer, from 1 to 65535. A blackhole-threats shorthand for transport.config.remoteport.
transport.config.remoteportinteger179The same setting in GoBGP’s own place. remote-port is accepted as another spelling.
afisafislistthe neighbor’s own familyThe address families to send. Each entry is config.afisafiname, such as ipv4-unicast or ipv6-unicast.

config.port and transport.config.remoteport can both be set as long as they agree; if they don’t, the file is rejected with conflicting neighbor endpoint port.

Other GoBGP settings

Section titled “Other GoBGP settings”

The gobgp block is GoBGP’s own BgpConfigSet, so any of its settings can go here. The key for each is GoBGP’s Go field name in lower case without separators, which isn’t the hyphenated name in GoBGP’s documentation: neighboraddress, not neighbor-address. Some that come up with a route server:

Key under a neighborWhat it is
config.descriptionA free-text label for the peer
config.authpasswordA TCP MD5 password for the session (Linux only)
config.localasA different local ASN for this peer
config.admindowntrue to configure the peer without bringing the session up
transport.config.localaddressThe source address to dial from
transport.config.passivemodetrue to wait for the peer to connect rather than dialling it
ebgpmultihop.config.enabled, ebgpmultihop.config.multihopttleBGP multihop

GoBGP checks these itself when the daemon starts; -check-config only checks that the keys exist and the values have the right types.

feeds

Section titled “feeds”

A list, one entry per feed.

KeyTypeDefaultWhat it is
urlstringnone, requiredA file path, or an http:// or https:// URL. A relative path is read from the working directory.
communitystring<local ASN>:666The BGP community the feed’s routes carry, written <as>:<value> with each part from 0 to 65535.
allow_emptybooleanfalseWhether the feed may give no prefixes. Without it, a feed that gives none counts as failed and its community keeps its previous routes; with it, the routes are withdrawn.

community: 0:0 means the same as leaving it out. Feeds added with -feed have no community and always use the default, and can’t set allow_empty. A local ASN above 65535 doesn’t fit in a standard community, so there’s no default: every feed needs its own community, and -feed can’t be used.

limits

Section titled “limits”

The shortest prefix blackhole-threats will announce, for each address family. Both keys are optional, and a key you leave out keeps its default.

KeyTypeDefaultWhat it is
min_ipv4_prefix_lengthinteger8The shortest IPv4 prefix announced, from 1 to 32
min_ipv6_prefix_lengthinteger16The shortest IPv6 prefix announced, from 1 to 128

A prefix from a feed that’s shorter than its family’s limit is dropped with a warning and the rest of the feed is used as normal, so a feed line of 0.0.0.0/0 or ::/0 is never announced. Summarising never merges prefixes into one shorter than the limit either. There’s no way to turn the check off: 0 isn’t accepted. Feeds and communities has the details.

What stops the file loading

Section titled “What stops the file loading”

-check-config and startup both reject:

  • a file that can’t be read, or isn’t valid YAML
  • an unknown key anywhere, including a hyphenated GoBGP key
  • as missing or 0
  • routerid missing or not an IPv4 address
  • a neighbor config.port that isn’t a number from 1 to 65535, a remoteport that isn’t 0 to 65535, or the two disagreeing
  • a feed with an empty url, or a scheme other than http or https, such as ftp:// or file://
  • a community that isn’t two numbers from 0 to 65535 separated by one colon
  • a feed with no community (or 0:0) when the local ASN is above 65535, including any feed from -feed
  • a limits.min_ipv4_prefix_length outside 1 to 32, or a limits.min_ipv6_prefix_length outside 1 to 128

The troubleshooting guide has the message each one logs.

blackhole-threats

Turns threat feeds into BGP blackhole routes: it reads text and JSON feeds, summarises the prefixes and announces them to your routers with a community they can drop on.
